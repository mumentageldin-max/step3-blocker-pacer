# Step 3 Pacer — Day, Block, Review, CCS and Stats

Five pages, one installable app:

- **Day** (`day.html`, since Nov 7; reshaped Nov 12) — the study day as one sequence, in the order it is really done: arrive · the blocks in a row with the same break between them (6 by default) · the CCS cases, each with its feedback right after (2 by default) · lunch · the **fast pass** (since Nov 13: every block of the morning, 10:00 each, the next one starting by itself — right answers are passed, a lucky guess gets the Educational Objective only, a wrong answer the Educational Objective and the paragraph of the answer that was picked; it sorts which questions get the long review, and it replaces the 4-question biostats contact, now off by default) · one review per block, lowest score first, with dinner in the middle · close. A tickable list, color-coded like the printed sheet, and one **Now** card that runs the current step's timer. **Start** runs the step, **Done** ticks it and moves on; a break or meal starts by itself when the task before it ends on its timer, and it is the same shared break the other pages show.
  - **Flexible at any moment.** A case is 12:30 or 25:00 (from the calendar: `94L` = a 20-minute case) and the card switches between the two before Start, in the middle of the case (the time used stays) and after it ended. A review takes 30 · 45 · 60 · 90 minutes; any other step −5:00 / +5:00 before Start and −5:00 · −1:00 · +1:00 · +5:00 while it runs; **Feedback ▸** / **Stand ▸** ends a part early. **Lunch now · break later ⇄** on a break card (and the reverse on the lunch card; dinner the same way) trades the two in one tap, **Move ▲ / Move ▼** moves any step for today. A tap on another row during a break ends the break. Settings are saved while a timer runs; Settings → The study day sets the number of blocks and cases, where lunch sits, the review length and the biostats step — today's ticks stay with their steps, also when the day's list is switched.
  - **Reviews, lowest score first.** The scores of the day's blocks are typed once on the first review card (or on the Block page's summary); each review step then names its block — "Review 1 · Block 4 · 9/20" — and by default gets 5:00 per wrong question + 1:00 per right one. The Review page lists the same blocks in the same order with the lowest already chosen.
  - **Measured.** A step that ran on a timer, here or in its own page, counts the time it really took (a break ended by the next block counts up to that block's start); a hand tick counts the plan; a skip counts nothing. Totals (study, breaks, ticked, day clock) and "on this pace, done at" follow.
  - **To the exam.** The bottom of the page is a calendar in weeks from Day 1 to the last exam day: past days show what was done (`6B 2C` + `4R` = blocks, cases, reviews), coming days the plan, exam days in red, with the countdown ("6 days to Exam Day 1") there and in the page's top line.
  - A block, review or case run in its own page is mirrored on the card ("Running in the Block page · 27:30"), ticks its step when that page saves it, and ends the break before it. The end of a step has its own sound — a rising four-note melody played twice — with two soft notes one minute before and a repeat once a minute (five at most) until the step is ticked; all of it also as notifications while the page is hidden. Other sequences come from the calendar: tonight (Nov 7), rehearsal (Nov 14), interface and minimum days (Nov 16–17), exam days, days off, the between-exam days. The day rolls over at 4:00 AM. A day begun on the page before Nov 12 is fitted to the new order once, when the new page first opens.

- **Block** (`index.html`) — 37:30 countdown for a 20-question UWorld block, checkpoint targets, ahead/behind verdicts, flag-at-50 mode, the 2:00 fill-every-blank alert. The time on the current question is big and in minutes (m:ss): amber from 1:00, orange from 1:30, red from 1:52 (37:30 ÷ 20) with its own soft sound once per question; violet "flag & move" from 0:50 after a behind checkpoint. Each stage has a word, not only a color. Since Nov 7 the last tap does not end the block: the clock keeps running for flags and blanks and the block ends when you press **End block** (the moment you press End Block in UWorld) or at 0:00 — Settings → "After the last question is tapped" brings back the old end-at-last-tap behaviours.
- **Review** (`review.html`) — Timer A (90:00 in three 30-minute chunks with a 10-minute stand between them) and Timer B (5:00 + 3:00 per wrong question, 60 s per right one), K/M/T/G tagging, parking lot, EO-only sweep at the hard stop, notebook line. Default order since Nov 7: **wrong questions first** (UWorld Results → Show: Incorrect), then the right ones with whatever time is left — the chooser offers only the kind that is due and shows "time left ÷ right questions left"; "Any order" in the setup restores the free chooser.
- **CCS** (`ccs.html`) — the length of the next case comes from the Day page's plan (case 2 of the day starts as 12:30 even when case 1 was 25:00; with no plan it is 12:30), and a **12:30 / 25:00** switch sits under the clock for the whole case — the time used stays, and a tap on the shorter length after it has passed never ends the case. A case screen that needs no tapping: one big clock counting up from 0:00 ("of 12:30" / "of 25:00", like the real-time clock on ccscases.com; USMLE's own CCS walkthrough shows no running real-time clock — you are told the maximum time before the case and warned at about two minutes left), the phase as a large color band (read → first orders → reassess loop → close → final orders), phase chimes, the final-orders alert and the end of the case all on their own. Pause (practice only) and Exit case are large and far apart; Exit and Discard keep the double-tap safety. A setting restores the old countdown. The order checklist is an optional fold, closed by default. The case log keeps only what ccscases.com cannot know: case number, case length, the words you misspelled (they feed the spelling drill), an optional score copied from ccscases, an optional note. A pre-case card, protocol lines per phase, the feedback-review timer, the spelling-keys lookup (435 orders) and the drill (sets, keys / spelling mode, best score per set) are unchanged.
- **Case template** (`template.html`) — the 12:30 case tracker as a printable landscape page; opens from the CCS page.
- **Breaks** (all pages) — the day's rule: 20 minutes after a task. When a block, a review, or a CCS case with its feedback ends, a break starts by itself, shows as a band on every pacer page with its clock and the time you are due back, chimes once when it is over (and notifies when the app is hidden), and ends when the next block, review or case starts. +5:00 and Skip on the band; the length is in Settings → Breaks on any page. The 10-minute stand after a 30-minute review chunk is the Review page's stand timer.
- **Stats** (`stats.html`) — every finished block, review and CCS case (edit or delete from the Sessions list), pacing per checkpoint, letters per review, scores, review discipline, a weekly report to paste to Claude. CCS lines read "case · length · score if entered · misspelled words"; CCS scores and feedback live in the ccscases.com Report Card and the app no longer draws conclusions from checklist taps (old sessions keep their fields and stay readable). Two counts run from the start of the plan, each beginning with a list read off its own site on Nov 13, 2026 and growing with what the pacer sees afterwards: **UWorld blocks since Oct 14** (test number, day created, subject — no scores; from Nov 14 a block saved on the Block page or a block step finished on the Day page adds one) and **different CCS cases since Oct 13** (case number, last day, length — no grades). Both also sit under the Day page's calendar.

Live at **https://mumentageldin-max.github.io/step3-blocker-pacer/** — served by GitHub Pages from the
`gh-pages` branch of this repository. To update the app, change the files, bump `VERSION` in `sw.js`,
and push the same commit to both `main` and `gh-pages`.

## Install

- **iPad Pro:** open the address in Safari → Share → **Add to Home Screen**. Do it from the Day, Block, Review and CCS pages if you want four icons.
- **Galaxy Z Fold 7:** open it in Chrome or Samsung Internet → ⋮ menu → **Install app**. The Review page offers its own install too.
- **iMac / Mac mini:** Safari → File → **Add to Dock**; or Chrome → the install icon at the right of the address bar.

After the first open it works offline.

## When the pacer is hidden behind UWorld or ccscases

Browsers freeze a hidden tab's timers and sound, and iPadOS gives a web app no background execution at all, so the app works in layers:

1. **Catch-up on return** (every device): all timing is wall-clock based. When the page becomes visible again it recomputes everything, fires each missed chime once, and shows one line — "While you were away (4:12): Q7: 1:52 budget passed at 10:14 · 2:00 left — fill every blank at 10:35". A review chunk that ended while hidden stops Timer A at the chunk end, not when you return.
2. **Notifications** (Settings → Background & sound → *Notify me when the app is hidden*): while a run is active and the page is hidden, the upcoming checkpoints, phase changes, the 1:52 budget, alerts, chunk ends and timer ends are scheduled as notifications (page timers plus the service worker, best effort). Timer-end notifications stay until dismissed; tapping one opens the pacer.
3. **Keep running in the background (Android)** (same settings block, off by default): a near-silent looping audio track with Media Session metadata ("Step 3 Pacer · block running") keeps the tab unthrottled on Android, so the real chimes fire on time. It stops when the run ends. Not offered on iPad / iPhone.
4. **Float the timer** (where the browser supports picture-in-picture): a small clock with the stage color that stays on top of the other app.

Per device, honestly:

- **iPad:** a hidden web app cannot play sound. Open the pacer from the Home Screen icon and allow notifications; otherwise keep it in split screen beside UWorld / ccscases. The catch-up covers whatever was missed.
- **Galaxy Z Fold 7:** allow notifications and turn on *Keep running in the background*. Chimes then play on time; notifications are the backup.
- **iMac / Mac mini:** allow notifications (Safari or Chrome); the catch-up covers the rest.

Chime volume (normal · quiet · whisper) is in the same settings block and applies to every page; the 1:52 sound is the only sine-wave sound in the app, so it is easy to tell apart.

## Progress and sync

Blocks, reviews and CCS cases save themselves on the device they ran on. Stats → *Sync across devices* merges all devices through a private GitHub gist: create one token with only the **gist** permission (link on the page), paste it on each device, press Sync. Stats → *Data* also exports and imports a JSON backup.

**Live sync of a run in progress:** with the same token, a block, review or case that is running is carried to the other devices through a second file in the same gist (`step3-pacer-live.json`). Start a review on the iPad, open the Review page on the Fold, and it picks the review up where it is — clocks included, because elapsed time is computed from timestamps — with a line "Picked up the review you started on your iPad at 10:14". Each page shows "Live sync on · last push 10:15:03" or "Live sync off — add the token in Stats". One pull on load and whenever the page becomes visible, one every 60 s while a run is active, one push about 2 s after a change; a finished run clears its slot so the other devices stop reviving it. Every device has an id and an editable name (Stats → Sync across devices; the default comes from the device: iPad / Android / Mac).

## Notes

- Settings (block length, checkpoint targets, review timers, case clock direction, day durations and calendar, theme) are per device, and since Nov 12 they can be saved while a block, a review or a case is running — the run uses the new values at once. Background & sound settings are per device too, but shared by all five pages. The Day page's ticks and running step travel between devices through the live-sync file like a running block does.
- Installed copies pick up a new `VERSION` of `sw.js` on their next open.
